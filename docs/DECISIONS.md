# Decision Log

All decisions below were made during the discovery discussion on **2026-11-17**. Add new decisions at the bottom with a date. Never rewrite old ones; supersede them with a new entry.

| # | Decision | Why | Alternatives considered |
|---|---|---|---|
| D-001 | **Qualification engine, not a CRM.** Output via Excel and webhooks only. | Smaller scope and faster MVP. Works with every CRM, so it competes with none. | Building lead assignment, pipelines, tasks |
| D-002 | **Generic platform with industry templates. Travel first.** | A real requirement from a travel client. Templates let us add industries without code. | A vertical-only product |
| D-003 | **Phase 1 lead sources:** Meta lead forms, Click-to-WhatsApp ads, inbound API. | The travel client runs both ad types. The API covers websites and other sources. | Meta only |
| D-004 | **Become a direct Meta Tech Provider.** Client WABAs stay in the client's own portfolio, and Meta bills clients directly. | No BSP markup or dependency. Our branding in onboarding. Simpler billing for us. | Going through a BSP (360dialog, Gupshup) |
| D-005 | **Coexistence is the default onboarding.** Full Cloud API migration is an option. | SMBs keep their existing number and phone app. No extra Meta fee. | A new number per client |
| D-006 | **Hierarchy Platform → Partner → Tenant → Users from day 1.** Launch to direct businesses only. | Agencies (Phase 2) and white-label (Phase 3) become feature flags instead of rewrites. These are the biggest revenue levers. | A flat tenant model |
| D-007 | **Hybrid playbook configuration.** Structured fields with required/priority and guidance, plus free-text rules, plus a knowledge base. The AI converses naturally. | Control over what is collected and what must not be said, while keeping the conversation natural. | A fixed question flow; a fully goal-based agent |
| D-008 | **Hybrid scoring:** rule points (default max 70) + anchored AI intent (default max 30), with a reason string. | Predictable and explainable, yet catches intent. Anchored criteria keep AI scores consistent. | Rules only; AI only |
| D-009 | **Language auto-detect** within tenant-allowed languages. Hinglish is treated as its own language. Output data is normalized to English. | Indian leads mix scripts and languages. CRMs need clean data. | A fixed language per tenant |
| D-010 | **Phase 1 is text only.** Non-text gets a polite reply and is counted. | A faster, cheaper MVP. Voice-note volume data will decide Phase 2. | Speech-to-text in the MVP |
| D-011 | **Backend: .NET 10 (C#) on Linux with Docker Compose.** | Team familiarity, performance, built-in workers and SignalR, official Claude C# SDK. Linux keeps cost low. | Node.js / Python; Windows hosting |
| D-012 | **PostgreSQL + Dapper + Row-Level Security** instead of SQL Server + ADO.NET stored procedures. | No licence cost. JSONB for per-tenant fields, pgvector later. RLS prevents cross-tenant leaks if a query misses a filter. Logic stays in C#, so it can be versioned and tested. | SQL Server / Azure SQL; pure SPs; EF Core |
| D-013 | **Hangfire (Postgres storage) for jobs and follow-ups, and Redis for locks, debounce and rate limits.** No separate message broker in Phase 1. | Fewer moving parts on a single cheap server. | RabbitMQ / Azure Service Bus |
| D-014 | **Frontend: React + Vite + TypeScript + Tailwind + shadcn/ui + Motion.** Static build served by Caddy. Theme tokens from day 1. | Modern professional UI, richest ecosystem, no Node server to host, white-label ready. | Angular, Blazor, Next.js (SSR) |
| D-015 | **The Phase 1 knowledge base is injected into the cached prompt.** pgvector comes later. | Small travel KBs fit. Simpler and more accurate. Caching keeps it cheap. | Vector search from day 1 |
| D-016 | **AI: Claude via the official C# SDK, with per-task model config.** The final model choice comes from the M3 eval. | Model choice drives unit economics. A decision from measurement, not assumption. | — |
| D-017 | **Name: AppsDemo Qualify.** One subdomain `qualify.appsdemo.in` with path routing (`/api`, `/webhooks/meta`). Staging is `qualify-staging.appsdemo.in`. | Builds on the verified AppsDemo brand. One TLS certificate and no CORS. Domain lives in config, not code. | A separate brand or domain |
| D-018 | **Build model: the owner + Claude Code, milestone by milestone** (M0–M8), each with a testable demo. | Speed and low cost. Context persists through CLAUDE.md and docs/. | An external dev team |
| D-019 | **No billing in the MVP; pricing deferred.** The first client is invoiced manually. | Saves 1–2 weeks. Pricing depends on the model choice from the M3 eval. | Razorpay subscriptions in the MVP |
| D-020 | *(Proposed)* **Cookie-based auth** (httpOnly, SameSite, antiforgery) for the same-origin SPA. | More secure than tokens in browser storage. Simple because SPA and API share one origin. | JWT in localStorage |
| D-021 | *(2026-11-17, supersedes D-016)* **LLM provider: an OpenAI-compatible API, either OpenRouter or OpenAI direct.** Integration uses the official `OpenAI` .NET SDK behind `Microsoft.Extensions.AI` (`IChatClient`). Base URL, API key and model per task come from config. | The owner's choice. One integration covers both: OpenRouter to compare many models in the M3 eval, and OpenAI direct is possible in production. No provider lock-in. | Claude via the Anthropic SDK (D-016) |
| D-022 | *(2026-11-17, supersedes D-011)* **Backend: full-stack TypeScript on Node.js 24 LTS, NestJS (Fastify adapter), in a pnpm monorepo** (`apps/api`, `apps/worker`, `apps/web`, `packages/*`). | The workload is I/O-bound (webhooks, LLM calls, outbound HTTP). One language with React and shared Zod types. Best SDK and example coverage for OpenAI, OpenRouter and Meta. NestJS mirrors ASP.NET Core patterns, which the owner knows. Easy hiring in India. .NET was not mandatory. | .NET 10 (D-011), Python FastAPI, Go |
| D-023 | *(2026-11-17, supersedes the Dapper part of D-012)* **Data access: Drizzle ORM + drizzle-kit migrations.** PostgreSQL + RLS is unchanged. | SQL-like and type-safe, a lightweight Dapper-like feel, and friendly to RLS (`withTenant()` transaction helper). | Prisma, Kysely, raw `pg` |
| D-024 | *(2026-11-17, supersedes D-013)* **Jobs: BullMQ on Redis** for queues, debounce (deduplication), follow-ups (delayed jobs), retries and scheduled reports (repeatable jobs), with Bull Board for monitoring. | Native delayed and deduplicated jobs, workers scale horizontally, no database polling. Redis was already in the stack. | Hangfire (D-013), pg-boss |
| D-025 | *(2026-11-17, supersedes the integration part of D-021)* **AI integration: Vercel AI SDK with the OpenRouter / OpenAI providers.** Structured output from shared Zod schemas. The provider choice in D-021 is unchanged. | Provider switching is a config change, and Zod-based structured output plugs straight into our shared schemas. | OpenAI Node SDK with a custom `baseURL` |
| D-026 | *(2026-11-17, supersedes D-020)* **Auth: Better Auth.** Cookie sessions (httpOnly, SameSite), CSRF protection, organization plugin with organization = tenant. | Multi-tenant orgs, members, roles and invitations built in. Self-hosted, with no per-user SaaS fees. | Custom auth, Auth.js, Clerk (paid) |
| D-027 | *(2026-11-17)* **Supporting libraries:** Socket.IO (real-time, replaces SignalR), Zod (validation), ExcelJS, Pino → Seq, Vitest + Testcontainers + Playwright, `@fastify/helmet` + `@fastify/rate-limit`, Dependabot + `pnpm audit`. | These are the standard, well-maintained choices for each concern in the TypeScript stack. | — |
| D-028 | *(2026-11-17, amends D-022)* **Runtime: Node.js 26 LTS** (26.13.1, pinned in `.nvmrc`) instead of Node 24. **TypeScript pinned to 6.0.x**, and **pnpm 12** pinned through `packageManager`. | Node 26 became Active LTS in October 2026 (support until April 2029), while Node 24 is in maintenance. TypeScript 7 (the native compiler) is not yet supported by the NestJS CLI or typescript-eslint. | Node 24 LTS; TypeScript 7 |
